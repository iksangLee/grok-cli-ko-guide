# 16-세션

Grok Build는 대화를 **자동으로 저장**합니다.  
터미널에서 사용하든, Headless 모드로 사용하든, Agent 모드로 사용하든, 모든 대화는 세션(Session)이라는 단위로 저장되어 나중에 다시 불러올 수 있습니다.

이 문서는 세션이 무엇인지, 어떻게 저장되고 관리되는지, 그리고 실무에서 어떻게 활용하면 좋은지를 처음 사용자 관점에서 정리합니다.

---

## 세션이란 무엇인가?

### 세션의 개념

**세션**은 Grok과의 **하나의 지속적인 대화**를 의미합니다.

하나의 세션에는 다음과 같은 정보가 모두 저장됩니다:

- 사용자가 입력한 모든 메시지
- Grok이 답변한 모든 내용
- Grok이 실행한 도구 호출(Tool call)과 그 결과
- TODO 리스트(작업 목록)의 상태
- 파일 변경 스냅샷 (rewind 기능용)
- 사용한 토큰 수와 턴 수
- 하위 에이전트(Subagent) 세션 (사용 시)

세션은 고유한 **세션 ID** (UUID)로 식별되며, `~/.grok/sessions/` 폴더 안에 저장됩니다.

### 왜 세션이 중요한가?

- 대화가 길어져도 **이전 내용을 잃지 않고** 이어갈 수 있습니다.
- 중요한 대화를 나중에 다시 불러와서 **참고**하거나 **이어서** 진행할 수 있습니다.
- 실수로 잘못된 방향으로 갔을 때 **되돌릴 수** 있습니다 (`/rewind`).
- 여러 프로젝트를 동시에 진행할 때 **프로젝트별로 대화를 분리**해서 관리할 수 있습니다.

---

## 세션 저장 위치와 구조

세션은 다음과 같은 경로에 저장됩니다:

```
~/.grok/sessions/<인코딩된-작업-디렉토리>/<세션-ID>/
```

예를 들어, `/Users/leeiksang/my-project`에서 작업했다면:

```
~/.grok/sessions/%2FUsers%2Fleeiksang%2Fmy-project/
    └── <session-id>/
        ├── summary.json          # 세션 메타데이터 (제목, 시간, 모델 등)
        ├── updates.jsonl         # 실제 대화 + 도구 호출 기록
        ├── chat_history.jsonl    # 모델에 보낸 원본 메시지
        ├── plan.json             # TODO 리스트 상태
        ├── rewind_points.jsonl   # 되돌리기용 파일 스냅샷
        └── ...
```

**중요 파일 설명**:

- `summary.json`: 세션의 기본 정보 (제목, 생성/수정 시간, 사용 모델 등)
- `updates.jsonl`: 가장 중요한 파일. Grok이 실제로 사용한 모든 정보가 여기에 기록됩니다.
- `chat_history.jsonl`: 모델에게 보낸 실제 프롬프트 기록

## 세션 시작과 종료

### 새 세션 시작하기

Grok Build를 처음 실행하면 자동으로 새로운 세션이 생성됩니다.

대화 중간에 완전히 새로운 대화를 시작하고 싶다면:

```bash
/new
```

또는 슬래시 명령어로:

```
/new
/clear   # /new의 별칭
```

- 이전 대화 내용은 모두 초기화됩니다.
- 새로운 프로젝트나 완전히 다른 주제를 시작할 때 사용합니다.

---

### 이전 세션 불러오기

이전에 하던 대화를 다시 이어서 하고 싶다면:

```bash
/load
```

세션 ID를 알고 있다면 직접 지정할 수도 있습니다:

```
/load abc123def456...
```

- `/load`를 입력하면 저장된 세션 목록이 나오고, 원하는 세션을 선택할 수 있습니다.
- 별칭: `/resume`

**실전 팁**:
- 중요한 대화를 하다가 다른 작업을 해야 할 때 `/new`로 새 세션을 만들었다가, 나중에 `/load`로 불러와서 이어서 진행하는 방식이 매우 유용합니다.

---

## 세션 압축 (`/compact`)

대화가 길어지면 컨텍스트 창(토큰)이 부족해질 수 있습니다. 이때 사용하는 것이 `/compact` 명령어입니다.

### 기본 사용법

```bash
/compact
```

- 현재 대화 기록을 압축(요약)하여 토큰을 절약합니다.
- Grok은 자동으로 대화의 중요한 부분을 남기고 불필요한 부분을 요약합니다.

### 고급 사용법

특정 내용을 꼭 유지하고 싶을 때:

```bash
/compact keep the authentication logic and project structure
```

- `keep` 뒤에 중요한 키워드나 문장을 적으면, 압축 과정에서 그 부분이 삭제되지 않도록 보호합니다.

**실전 팁**:
- 대화가 50턴 이상 길어지기 시작하면 `/context`로 현재 토큰 사용량을 확인해보세요.
- 80% 이상 차면 `/compact`를 하는 것이 좋습니다.
- 중요한 기술적 결정이나 아키텍처 논의가 있었다면, `/compact keep ...`를 적극 활용하세요.

---

## 되돌리기 기능 (`/rewind`)

실수로 잘못된 방향으로 대화를 진행했을 때 유용한 기능입니다.

### 기본 사용법

```bash
/rewind
```

- 이전 상태로 되돌아갑니다.
- 파일 변경, 도구 실행, 메시지 등을 단계적으로 되돌릴 수 있습니다.

### rewind_points

Grok은 중요한 지점마다 자동으로 **rewind point**를 저장합니다. 이를 통해 대화의 특정 시점으로 쉽게 돌아갈 수 있습니다.

**실전 팁**:
- 큰 리팩터링을 하다가 “이 방향이 아닌 것 같아” 싶을 때 `/rewind`를 사용하면 매우 유용합니다.
- rewind는 단순히 채팅 기록뿐만 아니라, 실제 파일 변경까지 되돌려줄 수 있습니다.

---

## 세션 정보 확인 명령어

### `/context`

현재 세션의 컨텍스트 사용량을 보여줍니다.

```bash
/context
```

- 현재 사용 중인 토큰 수
- 전체 컨텍스트 창 크기 대비 사용 비율
- 자동 압축이 일어날 시점

### `/session-info`

세션의 상세 정보를 보여줍니다.

```bash
/session-info
```

- 사용 중인 모델
- 턴 수 (메시지 교환 횟수)
- 총 토큰 사용량
- 세션 생성/수정 시간
- 세션 ID

**실전 팁**:
- `/context`는 토큰이 부족해지기 전에 미리 확인하는 용도
- `/session-info`는 현재 세션의 전체적인 상태를 파악할 때 유용

## 여러 세션 관리 팁

### 1. 프로젝트별 세션 분리 추천

가능하면 **프로젝트마다 별도의 세션**을 사용하는 것이 좋습니다.

- 한 세션에 너무 많은 프로젝트의 대화가 섞이면 컨텍스트가 혼란스러워집니다.
- `/new`로 새 세션을 만들 때, 해당 프로젝트 폴더에서 실행하면 세션이 프로젝트별로 깔끔하게 분리됩니다.

### 2. 중요한 대화는 미리 `/compact` 해두기

중요한 기술적 결정이나 아키텍처 논의가 오고 갔다면, `/compact keep ...`로 미리 압축해두는 것이 좋습니다.

### 3. 세션 ID 활용

`/load`할 때 세션 ID를 직접 입력할 수 있습니다. 중요한 세션은 미리 세션 ID를 메모해두면 나중에 쉽게 불러올 수 있습니다.

### 4. 긴 대화는 주기적으로 정리

- 100턴 이상 된 대화는 `/compact`를 주기적으로 하는 것이 좋습니다.
- 불필요한 Thinking Block이 너무 많다면, `/compact`가 자동으로 정리해줍니다.

## Subagent 세션 (하위 에이전트 세션)

Grok Build는 **Subagent** (하위 에이전트) 기능을 지원합니다. 이는 하나의 메인 세션 안에서 여러 개의 하위 세션을 동시에 실행할 수 있게 해줍니다.

### Subagent 세션이란?

- 메인 세션에서 특정 작업을 별도의 독립된 세션으로 분리해서 실행
- 예: 메인 세션에서는 전체 아키텍처를 논의하고, Subagent에서는 특정 모듈의 구현을 맡김
- 각 Subagent는 독립적인 컨텍스트를 가지기 때문에, 메인 세션의 컨텍스트를 과도하게 소비하지 않음

### Subagent 사용 예시

```
/subagent start "Payment module refactoring"
```

이렇게 하면 별도의 하위 세션이 생성되고, 그 안에서 독립적으로 작업할 수 있습니다.

Subagent 세션은 `subagents/` 폴더 안에 별도로 저장되며, 필요할 때 메인 세션으로 결과를 가져올 수 있습니다.

## 세션 공유 및 내보내기

### 세션 공유

Grok Build는 세션을 다른 사람과 공유할 수 있는 기능을 지원합니다.

- `/session-info`에서 세션 ID를 확인
- 세션 폴더 자체를 압축해서 공유 가능
- 일부 환경에서는 세션 URL 공유 기능도 지원

### 세션 내보내기

중요한 대화 내용을 보존하고 싶을 때:

- `updates.jsonl` 또는 `chat_history.jsonl` 파일을 직접 복사
- `/compact`로 정리한 후 중요한 부분만 남겨서 보관

**실전 팁**: 중요한 기술적 결정이 오고 간 대화는, `/compact keep ...`로 정리한 뒤 세션 폴더를 백업해두는 것을 추천합니다.

## 고급 세션 관리

### Rewind 상세

`/rewind`는 단순히 채팅 기록을 되돌리는 것이 아니라, **파일 변경까지 되돌릴 수** 있습니다.

- Grok이 파일을 수정했을 때, rewind를 하면 해당 파일도 이전 상태로 복원됩니다.
- `rewind_points.jsonl`에 중요한 시점들이 자동으로 기록됩니다.

### Compaction Checkpoints

자동 압축이 일어날 때마다 `compaction_checkpoints/` 폴더에 이전 상태가 저장됩니다.

- 압축 후에도 이전 대화의 일부를 복원할 수 있는 안전장치
- 필요할 경우 이전 checkpoint로 되돌아갈 수 있음

### Parent Session

다른 세션에서 이어서 시작한 세션은 `summary.json`에 `parent_session` 정보가 남습니다.

- “이 대화는 원래 어떤 세션에서 이어진 것인가?”를 추적할 수 있습니다.

## 전체 세션 가이드 마무리

### 세션 관리 추천 전략

1. **프로젝트별 세션 분리**
   - 가능하면 프로젝트마다 별도의 세션을 유지하세요.

2. **중요 대화는 주기적으로 정리**
   - `/compact keep ...`를 활용해서 핵심 내용을 보호하면서 토큰을 관리하세요.

3. **되돌리기 적극 활용**
   - 큰 변경을 할 때는 `/rewind`를 두려워하지 마세요. 안전장치가 잘 되어 있습니다.

4. **Subagent 활용**
   - 큰 작업은 Subagent로 분리해서 메인 세션의 컨텍스트를 보호하세요.

5. **세션 백업**
   - 중요한 대화는 세션 폴더를 주기적으로 백업해두세요.
