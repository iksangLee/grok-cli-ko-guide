# 01-시작하기

Grok Build는 xAI에서 만든 **터미널 기반 AI 코딩 어시스턴트**입니다.  
터미널에서 전체 화면으로 동작하는 TUI(Terminal User Interface) 프로그램으로, 여러분의 코드베이스를 이해하고, 파일을 읽고 편집하며, shell 명령을 실행하고, 웹 검색까지 할 수 있습니다.

처음 사용하시는 분이라면 “이게 정확히 뭐하는 프로그램이지?”라는 생각이 들 수 있습니다.  
간단히 말해, **터미널 안에서 움직이는 강력한 AI 페어 프로그래머**라고 생각하시면 됩니다. 코드를 대신 짜주기도 하고, 복잡한 리팩터링을 도와주기도 하며, 프로젝트 구조를 분석해 주기도 합니다.

이 문서는 Grok Build를 **처음 설치하고, 처음 실행해서, 실제로 유용하게 쓰기 시작하기까지**의 과정을 처음 사용자 관점에서 안내합니다.

---

## 1. Grok Build 소개

Grok Build는 세 가지 방식으로 사용할 수 있습니다.

| 사용 방식          | 설명                                      | 주로 쓰는 사람          |
|--------------------|-------------------------------------------|-------------------------|
| **Interactive TUI** | 터미널 전체 화면으로 대화하며 사용 (기본) | 대부분의 개발자         |
| **Headless**        | 명령줄에서 바로 실행 (스크립트, CI/CD)    | 자동화·배포를 하는 사람 |
| **Agent Mode**      | IDE나 다른 프로그램과 연동 (ACP)          | 에디터 플러그인 개발자  |

이 문서에서는 가장 많이 쓰이는 **Interactive TUI** 중심으로 설명합니다.

### Grok Build가 잘하는 일

- 코드베이스 전체를 읽고 이해한 후 질문에 답변
- 파일을 읽고, 수정하고, 새로운 파일을 생성
- 복잡한 리팩터링 작업을 단계적으로 제안하고 실행
- 테스트를 작성하고, 버그를 찾아 수정
- Git 작업, 배포 스크립트 실행 등 실제 작업 수행

### 아직 완벽하지 않은 부분 (미리 알려드립니다)

Grok Build는 매우 강력하지만, 아직 다음과 같은 한계가 있습니다:

- **매우 큰 프로젝트**에서는 한 번에 모든 맥락을 기억하지 못할 수 있습니다.
- **최신 프레임워크**나 잘 알려지지 않은 라이브러리에 대해서는 실수가 있을 수 있습니다.
- 한 번에 너무 큰 작업(“이 프로젝트 전체를 Next.js 15로 마이그레이션해줘”)을 시키면 실패 확률이 높아집니다.

→ **구체적으로, 조금씩 요청하는 것**이 Grok Build를 가장 잘 사용하는 방법입니다. (이 부분은 나중에 더 자세히 설명하겠습니다)

## 2. 설치하기

Grok Build는 macOS, Linux, Windows 모두 지원합니다.

### 가장 간단한 설치 방법

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

특정 버전을 설치하고 싶다면 아래와 같이 버전을 지정할 수 있습니다:

```bash
curl -fsSL https://x.ai/cli/install.sh | bash -s 0.1.42
```

### 설치 확인

설치가 끝나면 아래 명령어로 버전을 확인해보세요:

```bash
grok --version
```

정상적으로 버전이 출력되면 설치가 완료된 것입니다.

### Windows 사용자 주의사항

Windows에서는 **Git for Windows** (Git Bash) 또는 **MSYS2**에서 설치 명령을 실행해야 합니다.  
일반적인 cmd.exe나 PowerShell에서는 설치가 제대로 동작하지 않을 수 있습니다.

설치 후에는 `%USERPROFILE%\.grok\bin` 경로를 Windows PATH에 추가해야 `grok` 명령을 어디서든 사용할 수 있습니다.

### 업데이트하기

Grok Build는 언제든지 최신 버전으로 업데이트할 수 있습니다:

```bash
grok update
```

## 3. 설치 후 자주 발생하는 문제

설치 자체는 간단하지만, 설치 직후에 아래와 같은 문제가 자주 발생합니다.

### `grok: command not found`

이 메시지가 나오면 대부분 **PATH가 적용되지 않은** 경우입니다.

**해결 방법:**
1. 터미널을 완전히 종료하고 **다시 열기**
2. `source ~/.zshrc` 또는 `source ~/.bashrc` 실행해보기
3. 여전히 안 되면 설치 후 출력된 안내 메시지를 다시 확인

### Windows에서 `grok` 명령이 안 될 때

- Git Bash가 아닌 일반 cmd.exe나 PowerShell에서 실행하고 있는 경우가 많습니다.
- 반드시 **Git Bash**를 실행한 상태에서 `grok`을 입력해보세요.

### 설치 후 바로 업데이트가 안 될 때

드물게 설치 직후 `grok update`가 실패하는 경우가 있습니다.  
이때는 터미널을 완전히 재시작한 후 다시 시도해보세요.

### 여전히 안 될 때

위 방법으로도 해결되지 않으면, 아래 명령으로 설치 스크립트를 다시 실행해보는 것도 하나의 방법입니다:

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

## 4. 처음 실행하고 인증하기

설치가 완료되었다면, 이제 Grok Build를 처음 실행해보겠습니다.

### 기본 실행

```bash
grok
```

처음 실행하면 브라우저가 자동으로 열리면서 grok.com 로그인 화면이 나타납니다.

### 인증 과정

1. 브라우저에서 grok.com 계정으로 로그인합니다.
2. 로그인에 성공하면 Grok Build가 인증 토큰을 받아옵니다.
3. 이 토큰은 `~/.grok/auth.json` 파일에 저장됩니다.

이후부터는 별도의 로그인 없이 바로 사용할 수 있습니다.

### 토큰 만료 안내

인증 토큰은 기본적으로 **7일** 후에 만료됩니다.  
토큰이 만료되면 Grok Build가 자동으로 다시 인증을 요청합니다.

### API 키로 인증하기 (선택)

브라우저 없이 인증하고 싶거나, CI/CD 환경에서 사용하고 싶다면 **API 키** 방식으로도 실행할 수 있습니다.

```bash
export GROK_CODE_XAI_API_KEY="xai-여러분의-키"
grok
```

API 키는 [grok.com](https://grok.com)에서 발급받을 수 있습니다.

> **참고**: 처음 시작하시는 분이라면 브라우저 로그인 방식을 추천합니다. 나중에 필요할 때 API 키 방식을 사용해도 충분합니다.

## 5. 내 코드가 안전할까? (프라이버시)

이 부분은 Grok Build를 처음 사용하는 많은 분들이 가장 궁금해하고, 동시에 가장 불안해하는 주제입니다.

### 솔직하게 말씀드리겠습니다

**Grok Build는 완전히 로컬에서만 동작하지 않습니다.**

여러분이 “이 파일 분석해줘” 또는 “이 함수 고쳐줘”라고 요청하면, Grok Build는 해당 파일의 내용을 읽어서 xAI의 모델에 전달합니다.  
즉, **코드의 일부가 xAI 서버로 전송**된다는 의미입니다.

### 정확히 어떤 것이 전송되나요?

- 여러분이 `@`로 첨부한 파일 내용
- Grok Build가 “이 파일을 읽어야겠다”고 판단한 파일 내용
- 현재 대화의 맥락(context)

반대로, 여러분이 요청하지 않은 파일은 읽지 않습니다.  
또한 Grok Build는 여러분의 전체 프로젝트를 무작정 업로드하지 않습니다.

### xAI는 제 코드를 어떻게 다루나요?

- xAI는 모델 학습에 사용자의 코드를 사용하지 않는다고 공개적으로 밝혔습니다.
- 대화 내용과 코드는 모델 응답 생성에만 사용되고, 별도로 저장되지 않습니다.
- 다만, “절대 저장되지 않는다”고 100% 장담할 수는 없는 것이 현실입니다.

### 실전에서 어떻게 대처하면 좋을까?

**추천하는 사용 방식:**

- **개인 프로젝트, 오픈소스, 학습용 프로젝트** → 마음껏 사용하세요. Grok Build의 진짜 강점을 경험할 수 있습니다.
- **회사 기밀 프로젝트, 중요한 소스코드** → 중요한 파일은 @로 직접 지정하지 말고, “이 함수의 역할만 알려주고 싶은데 어떻게 설명하면 될까?” 식으로 추상화해서 물어보는 것이 안전합니다.
- **극도로 민감한 코드** → 아예 사용하지 않거나, 로컬 전용 모델을 사용하는 다른 도구를 고려하는 것이 좋습니다.

### YOLO 모드와 프라이버시

YOLO 모드(자동 승인 모드)를 켜면 Grok Build가 파일을 읽고, 명령을 실행하고, 수정을 가하는 모든 과정을 자동으로 진행합니다.  
이 모드를 사용할 때는 **특히 주의**해야 합니다. 실수로 중요한 파일이 수정되거나 삭제될 수 있기 때문입니다.

처음에는 **기본 모드**(매번 확인받는 방식)로 사용하면서 익숙해지는 것을 강력히 추천합니다.

## 6. TUI 화면 구성 살펴보기

Grok Build를 처음 실행하면 전체 화면 TUI가 나타납니다.  
처음 보면 다소 복잡해 보일 수 있지만, 크게 두 개의 영역으로 나뉩니다.

### 화면 구성

- **스크롤백 (위쪽 영역)**  
  지금까지의 대화 기록이 쌓이는 곳입니다.  
  여러분의 질문, Grok의 답변, Thinking block(사고 과정), Tool call(도구 실행) 결과 등이 모두 이 영역에 표시됩니다.

- **프롬프트 입력란 (아래쪽 영역)**  
  여러분이 메시지를 입력하는 곳입니다.  
  여기서 질문을 입력하고 `Enter`를 누르면 Grok에게 전달됩니다.

### 처음 보면 당황할 수 있는 것들

**Thinking block (사고 과정 블록)**

Grok이 “생각 중…”일 때 나타나는 블록입니다.  
내부적으로 어떤 계획을 세우고, 어떤 파일을 읽어야 할지, 어떤 도구를 사용해야 할지를 정리하는 과정입니다.

→ **이 블록은 무서워하지 않아도 됩니다.**  
  Grok이 성급하게 답변하지 않고, 제대로 생각하고 있다는 증거입니다. `h` 키를 눌러 접을 수도 있고, `l` 키로 펼칠 수도 있습니다.

**Tool call (도구 호출) 결과**

Grok이 실제로 파일을 읽거나, shell 명령을 실행하거나, 파일을 수정할 때 나타납니다.

예를 들어:
- 파일을 읽으면 → 읽은 내용이 표시됩니다
- 명령을 실행하면 → 실행 결과(성공/실패)가 표시됩니다
- 파일을 수정하면 → **변경 전후 diff**가 보여집니다

이때 Grok이 “이 작업을 실행해도 될까요?”라고 물어보면, `y` (예) 또는 `n` (아니오)로 답할 수 있습니다.

### 유용한 키보드 조작 (기본)

- `j` / `k` : 스크롤백 위아래 이동
- `h` / `l` : Thinking block이나 Tool call 결과 접기/펼치기
- `y` : 현재 항목 내용 복사
- `Enter` : 선택한 항목 전체 화면으로 보기
- `Esc` 또는 `Tab` : 입력란과 스크롤백 사이 포커스 이동

이 키들은 나중에 천천히 익혀도 됩니다. 처음에는 그냥 메시지를 입력하고 결과를 보는 것만으로 충분합니다.

## 7. 5분 만에 첫 성공 경험하기

설치와 인증을 마쳤다면, 이제 실제로 Grok Build를 사용해볼 차례입니다.

아래는 **처음 사용자가 가장 쉽게 성공할 수 있는** 따라하기 예시입니다.

### 따라 해보기 (추천 시나리오)

1. **현재 폴더가 어떤 프로젝트인지 물어보기**

   ```
   이 프로젝트가 어떤 코드베이스인지 간단히 분석해줘
   ```

   Grok은 프로젝트 루트의 파일들을 살펴본 후, 주요 기술 스택, 폴더 구조, 목적 등을 정리해서 답변해줄 것입니다.

2. **특정 파일을 붙여서 물어보기**

   `@` 기호를 입력하면 퍼지 파일 선택기가 열립니다.

   예시:
   ```
   @README.md 이 파일의 주요 내용을 요약해줘
   ```

   또는 여러 파일을 한 번에:
   ```
   @package.json @src/main.ts 이 프로젝트의 진입점이 어디인지 알려줘
   ```

3. **간단한 개선 제안을 받아보기**

   ```
   이 프로젝트에서 가장 먼저 개선하면 좋을 부분이 뭐라고 생각해?
   ```

   Grok이 몇 가지 제안을 해줄 것입니다.  
   여기서 마음에 드는 제안이 있으면 “그럼 그 부분을 자세히 분석해줘”라고 이어서 요청하면 됩니다.

### 첫 성공 후 느끼는 점

이 과정을 거치면 대부분 “아, 이렇게 쓰는구나” 하는 감을 잡게 됩니다.

중요한 것은:
- 처음부터 너무 거창한 요청을 하지 말 것
- 구체적인 파일을 `@`로 붙여서 물어볼 것
- 한 번에 하나씩 요청할 것

이 세 가지만 지켜도 첫 경험이 훨씬 성공적입니다.

## 8. Grok에게 잘 물어보는 방법

Grok Build의 성능은 **어떻게 질문하느냐**에 따라 크게 달라집니다.  
같은 프로젝트라도 질문 방식에 따라 결과가 완전히 달라질 수 있습니다.

### 좋은 질문 vs 나쁜 질문

**나쁜 예시 (피하세요)**

- “이 프로젝트 분석해줘” (너무 모호함)
- “코드 전체 리팩터링해줘” (범위가 너무 큼)
- “버그 찾아줘” (어떤 버그인지, 어디서 나는지 전혀 없음)

**좋은 예시**

- “@src/components/UserProfile.tsx 이 컴포넌트에서 props가 너무 많이 전달되고 있는 것 같은데, 어떻게 개선하면 좋을까?”
- “이 프로젝트에서 테스트가 부족한 부분이 어디인지, package.json을 보고 알려줘”
- “@app/api/auth/route.ts 이 로그인 로직에 보안상 위험한 부분이 있는지 단계적으로 분석해줘”

### 잘 물어보는 핵심 원칙

1. **구체적으로 말하기**  
   “좋은 코드로 만들어줘”보다 “이 함수의 가독성을 높여줘”가 훨씬 좋은 결과가 나옵니다.

2. **파일을 직접 지정하기** (`@`)  
   Grok이 전체 프로젝트를 다 뒤지게 하지 말고, 중요한 파일을 직접 붙여주는 것이 정확도와 속도 모두에서 유리합니다.

3. **한 번에 너무 큰 일을 시키지 않기**  
   “전체 아키텍처를 바꿔줘” 대신 “이 부분의 아키텍처 문제점을 먼저 분석해줘”로 시작하세요.

4. **단계적으로 요청하기**  
   좋은 패턴: 
   - 1단계: 분석 요청
   - 2단계: 개선 방향 제안 요청
   - 3단계: 실제 변경 작업 요청

5. **“왜 그렇게 생각했는지” 물어보기**  
   “왜 이 방식이 더 좋다고 생각해?”라고 물어보면 Grok의 판단 근거를 알 수 있어서 학습 효과가 큽니다.

## 9. 핵심 개념 정리

지금까지 실전 사용법을 중심으로 설명했습니다.  
여기서는 Grok Build를 더 깊이 이해하기 위해 꼭 알아야 할 핵심 개념들을 정리합니다.

### 세션 (Session)

Grok Build에서 **하나의 대화 흐름**을 “세션”이라고 부릅니다.

- 모든 대화 기록, Tool call 결과, 파일 수정 내역은 세션 단위로 저장됩니다.
- `Ctrl + N` 또는 `/new` 로 새 세션을 시작할 수 있습니다.
- 이전 세션은 `/load` 명령이나 `grok --resume`으로 다시 불러올 수 있습니다.
- 가장 최근 세션은 `grok -c` 로 바로 이어서 사용할 수 있습니다.

세션은 `~/.grok/sessions/` 폴더에 저장되며, 프로젝트별로 자동으로 관리됩니다.

### 도구 호출 (Tool call)

Grok Build가 단순히 답변만 하는 것이 아니라, **실제로 여러분의 컴퓨터에서 작업을 수행**하는 것을 “도구 호출”이라고 합니다.

주요 도구:
- 파일 읽기 / 쓰기 / 수정 (`read_file`, `search_replace`)
- shell 명령 실행
- 코드베이스 검색 (`grep`)
- 디렉토리 탐색
- 웹 검색

Grok이 무언가를 실행하려고 할 때마다 여러분에게 확인을 받습니다 (기본 모드).

### 슬래시 명령어 (Slash Commands)

프롬프트 입력란에서 `/` 를 입력하면 다양한 빠른 명령을 사용할 수 있습니다.

자주 쓰는 명령어:
- `/new` — 새 세션 시작
- `/compact` — 대화 기록 압축 (토큰 절약)
- `/yolo` — YOLO 모드 토글
- `/model` — 모델 변경
- `/plugins` — 플러그인 관리 화면 열기

전체 명령어 목록은 나중에 별도 문서에서 다룹니다.

### 메모리 (Memory)

Grok Build는 여러 세션에 걸쳐 중요한 정보를 기억할 수 있습니다.

- 프로젝트의 주요 규칙, 자주 쓰는 패턴, 팀 컨벤션 등을 기억합니다.
- `/memory` 관련 명령으로 직접 관리할 수도 있습니다.

(자세한 내용은 추후 “메모리” 문서에서 다룹니다.)

## 10. 권한 시스템 이해하기

Grok Build는 여러분의 컴퓨터에서 실제로 파일을 수정하고 명령을 실행할 수 있기 때문에, **권한 시스템**이 매우 중요합니다.

### 기본 모드 (추천)

기본적으로 Grok이 무언가를 하려고 할 때마다:

> “이 파일을 수정해도 될까요?”  
> “이 shell 명령을 실행해도 될까요?”

라고 물어봅니다.

처음에는 이 모드로 사용하는 것을 **강력 추천**합니다.  
실수로 중요한 파일이 변경되는 것을 방지할 수 있습니다.

### YOLO 모드 (자동 승인)

YOLO 모드는 모든 확인 과정을 생략하고 Grok이 알아서 작업을 수행합니다.

**켜는 방법:**
- `Ctrl + O` 단축키
- `/yolo` 슬래시 명령어
- `grok --yolo` 로 실행

**언제 사용하면 좋을까?**

- 신뢰할 수 있는 개인 프로젝트에서
- 반복적인 작업을 빠르게 처리하고 싶을 때
- Grok의 판단을 상당 부분 신뢰하게 된 이후

**언제 사용하면 안 될까?**

- 회사 프로젝트
- 중요한 파일이 많은 프로젝트
- 아직 Grok의 실력을 충분히 검증하지 못한 상태

YOLO 모드를 사용할 때는 **반드시** 어떤 작업을 하고 있는지 스크롤백을 주의 깊게 확인하세요.

## 11. Grok이 잘하는 것과 아직 약한 것

솔직한 기대치 설정이 중요합니다.

### Grok Build가 잘하는 일

- 중간 규모 프로젝트의 코드 이해 및 리팩터링
- 테스트 작성, 버그 분석
- 파일 구조 개선 제안
- Git 작업, 설정 파일 관리
- 특정 기술 스택에 대한 구체적인 조언 (TypeScript, React, Python, Rust 등)

### 아직 약하거나 주의가 필요한 부분

- **매우 큰 모노레포** (수십만 줄 이상)
- 최신 프레임워크의 아주 세부적인 최신 기능
- 복잡한 분산 시스템 아키텍처 설계
- 보안에 매우 민감한 코드 리뷰 (반드시 사람이 최종 검토 필요)
- 한 번에 너무 큰 범위의 작업 (“프로젝트 전체를 다른 프레임워크로 옮겨줘”)

### 잘 사용하는 팁

- 큰 작업은 **단계로 나누어서** 요청하세요.
- 중요한 변경은 항상 **Grok이 제안한 내용**을 직접 검토하세요.
- “이 변경을 적용하기 전에 리스크를 분석해줘”라고 먼저 물어보는 습관을 들이세요.

Grok Build는 “완벽한 개발자”가 아니라 **매우 똑똑한 페어 프로그래머**입니다.  
이 점을 이해하고 사용하면 훨씬 만족도가 높습니다.

## 12. 프로젝트 규칙 (AGENTS.md)

프로젝트마다 반복적으로 지켜야 할 규칙이나 컨벤션이 있을 때 유용한 기능입니다.

### AGENTS.md란?

프로젝트 폴더(또는 상위 폴더)에 `AGENTS.md` 파일을 만들면, Grok Build가 자동으로 그 내용을 읽어서 **항상 적용**합니다.

예시:
- “항상 TypeScript를 사용해”
- “함수형 컴포넌트만 작성해”
- “테스트는 Vitest로 작성해”
- “커밋 메시지는 Conventional Commits 형식으로”

### 어떻게 만들까?

프로젝트 루트에 `AGENTS.md` 파일을 만들고, 원하는 규칙을 적으면 됩니다.

더 자세한 내용은 “프로젝트 규칙” 문서에서 다룹니다.
